# Config Guideline: .mcp.json

## Purpose

Define a standard `.mcp.json` configuration for GitHub Copilot CLI so projects can use the same MCP server setup consistently.

---

## Authoritative Server IDs and Commands

Use these names exactly. Do not substitute older or assumed names — confirm against this
table before writing an `.mcp.json` or `github-app.yml` `mcp_servers:` entry.

| Server ID | NuGet Package | Command (executable) |
|---|---|---|
| `jsdotnet-project-guidelines` | `JSdotNet.MCP.Guidelines` (`jsdotnet.mcp.guidelines`, v1.0.11+) | `jsdotnet-guidelines-mcpserver` |
| `jsdotnet-project-design` | `JSdotNet.MCP.Design` (`jsdotnet.mcp.design`) | `jsdotnet-design-mcpserver` |

**⚠️ Deprecated — do not use:** `jsdotnet-project-guidelines-mcpserver` (from the deprecated
package `jsdotnet.project.guidelines.mcpserver`, last published at v1.0.6). This name has been
mistakenly reintroduced in generated configs; if you see it, replace it with
`jsdotnet-guidelines-mcpserver` under the `JSdotNet.MCP.Guidelines`/`jsdotnet.mcp.guidelines` package.

---

## Setup

1. Place a `.mcp.json` file in the repository root.
2. Add all required MCP servers under `mcpServers`.
3. Keep server keys stable across repositories to avoid prompt and tooling drift.

Use this baseline structure:

```json
{
  "mcpServers": {
    "microsoft-learn": {
      "type": "stdio",
      "command": "<microsoft-learn-command>",
      "args": [],
      "tools": ["*"]
    },
    "jsdotnet-project-guidelines": {
      "type": "stdio",
      "command": "jsdotnet-guidelines-mcpserver",
      "args": [],
      "tools": ["*"]
    },
    "jsdotnet-project-design": {
      "type": "stdio",
      "command": "jsdotnet-design-mcpserver",
      "args": [],
      "tools": ["*"]
    },
    "aspire": {
      "type": "stdio",
      "command": "<aspire-command>",
      "args": [],
      "tools": ["*"]
    }
  }
}
```

Replace placeholder commands with the official commands from each server's installation guide.

---

## Fields to Include

At minimum, each server entry should include:

- `type`: Transport type. Use `stdio` unless a server explicitly requires another transport.
- `command`: Executable that starts the MCP server.
- `args`: Command arguments (use `[]` when none are needed).
- `tools`: Tool allow-list. Use `["*"]` unless you need strict tool scoping.

Optional but recommended where needed:

- `env`: Environment variables for API keys, tenant settings, or endpoint configuration.

---

## Server-Specific Notes

### microsoft-learn

- Use this server for official Microsoft documentation and code sample retrieval.
- Keep credentials (if required) in environment variables, not inline in `.mcp.json`.

### jsdotnet-project-guidelines

- This server is authoritative for project guidance (ADRs, recommendations, structures, config) in `guide/`.
- Keep the server ID exactly `jsdotnet-project-guidelines` and the command exactly `jsdotnet-guidelines-mcpserver` so prompts and existing workflows continue to work without changes.
- Do **not** use the deprecated command `jsdotnet-project-guidelines-mcpserver` — see "Authoritative Server IDs and Commands" above.

### jsdotnet-project-design

- This server is authoritative for design and UX guidance in `design/`.
- Keep the server ID exactly `jsdotnet-project-design` and the command exactly `jsdotnet-design-mcpserver`.

### aspire

- Use this server for .NET Aspire orchestration and diagnostics workflows.
- Keep command/args aligned with the installed Aspire MCP server version.

---

## Best Practices for Ongoing Maintenance

- Version and review `.mcp.json` through pull requests like any other code artifact.
- Pin or standardize server installation versions where supported to avoid behavior changes across machines.
- Keep server names stable; change keys only with a documented migration.
- Keep `tools` permissive by default (`["*"]`) and restrict only when there is a clear security or governance need.
- Store secrets in environment variables or secret stores; never commit credentials in config.
- Revalidate server startup after command or argument changes.
- Remove unused servers to keep startup and tool resolution predictable.
